# 农场洞穴运行接入

2026-09-14：正式洞穴使用 `data/stardewcraft/structure/farm_layouts/cave.nbt`，不再仅作为工坊建筑稿。地图为第 2 次美术修订；运行布局版本为 1。

## 原因与传送约定

旧入口无条件使用 `ensureCaveLoaded` 返回的原点：结构放置失败仍返回坐标；`cavePlaced=true` 时也不检查实际地板、出口或落点。因而“记录已建成、实际房间缺失”可以把玩家直接送入虚空。旧入口还按玩家自己的农场选择洞穴，而不是脚下正在访问的农场。这些是源码确认的缺陷；尚未取得反馈者的具体存档来断言每次事故原因。

`FarmCaveRuntime` 现在在服务端分阶段处理：临时区块票据 → 等待目标与相邻区块就绪 → 安装或修复结构及出口 → 等待光照完成 → 验证脚下支撑、两格碰撞和流体 → 传送。等待阶段不用同步 `getChunk`，失败保留玩家在原处，支持重试；临时票据在完成、取消、超时或关服时释放。

入口根据玩家实际访问的农场及访问权限定位。洞内出口回到该农场配置的洞口落点。进出均支持走入传送方块和原有右键，落点与出口触发格分开，保留冷却避免来回传送。进入前再次检查权限与位置；走开、死亡或换维度取消等待。旧洞穴内的玩家以及新洞穴地板下的玩家有恢复路径；农场删除后的滞留玩家使用公共农场出口。

## 地图与旧档

- 新洞穴按稳定的农场 `instanceId` 分配，基点 `(18976,70,19392)`，Z 间隔 32；转让不换房间，删除后的槽位不复用。
- 旧洞穴基点 `(18944,70,19392)` 保留。`cave_legacy.nbt` 是随模组发布的旧结构比较基准，运行时不依赖制作目录。
- 首次迁移比较旧结构与现状，保留蘑菇盆待领取产物、箱子库存及可容纳的玩家方块。相连家具整体平移，六个旧蘑菇盆映射到新锚点。旧房间保持原样作为备份；已认领的旧房间不导入另一个新建农场。
- 迁移空间不足会停止接入并记录旧房间坐标，不将玩家送入半成品。实体形式的装饰物，以及第三方方块实体内自定义的绝对坐标关系，没有通用迁移保证，原房间仍保留。
- 后续准备只补缺失的固定岩壳、地板和出口，不重放空气清空玩家内容。固定建筑和门口禁放区受保护；可布置区域遵循农场访问/完全权限。
- 六盆与脱水机沿用原版地图坐标关系。脱水机为一次赠送，搬走后不重复补发。每日处理等待房间就绪，并保存最近处理日，避免同日重复推进；原有扩展回调继续可用。

## 验证

已运行 Java `classes`、12 种语言的 `checkTranslations`，以及 `python3 compatibility/verify_farm_cave_layout.py`。资源检查覆盖 3,744 格、59 格连通地面、进出口、七个设施锚点、四盏有支撑灯笼和旧结构基准。

在独立目录的无窗口专用服务端，真实星露谷维度下运行两个定向 GameTest，均产生明确的 `[FARM-CAVE-TEST] PASS`：

1. 冷区块进洞、旧库存/产物迁移、访问者自己的农场不干扰目标、访问与修改权限、转让后出口、缺失地板修复、不重复发脱水机、删除重建不重复导入旧库存。
2. 旧档只有建成标记而没有房间、阻塞落点拒绝传送、解除阻塞后重试成功。测试故意产生一次 `Unsafe cave arrival` 错误，用于验证失败路径。

维护入口：`compatibility/farm-cave-runtime-tests.gradle`。普通 `runGameTestServer` 不创建所需维度，不能作为这两项的替代；使用该配置启动无窗口专用服务端，再执行文件内的两个测试命令，确认两条 PASS 后 `stop`。本轮使用临时等价配置执行；维护配置另通过 Gradle 任务配置检查。没有启动独立测试客户端，未对反馈问题的真实整合包存档做客户端验收。

# 多人日结一致性与离线追赶设计

## 目标

在保持全服统一星露谷日期的前提下，补齐日结期间的在线受众、晚登录玩家、个人奖励、晕倒结果和离线农场追赶边界，同时避免重新引入单 tick 登录尖峰或长期强载区块。

## 日结受众

- 日结开始时，星露谷谷地和星露谷矿区中的全部在线玩家都进入冻结的个人结算名单，不再以是否拥有农场为条件。
- 冻结名单中的玩家执行完整个人结算：体力与生命恢复、出货、技能升级、配方、任务、精通和真实存在的晕倒结果。
- 奖励和惩罚使用持久化 `PendingSettlement` 阶段检查，只能提交一次；断线重连继续原阶段，不重放已完成副作用。
- 日结开始后才登录或进入结算维度的玩家只加入当前日期屏障，收到带正确绝对日的空 READY 结果，不生成当天出货、升级或晕倒结果。
- 晚登录玩家若先存在旧的个人 pending 结算，优先完成旧结算；确认后若当前日结仍活跃，再加入当前屏障。

## 屏障生命周期

- `DailySettlementBarrier.ReadyResult` 标记结果是个人结算还是仅日期同步。
- 个人结算 READY 必须通过 `hasCompletedReady` 校验后才能 ACK。
- 仅日期同步 READY 可以直接 ACK，但仍必须匹配服务端锁定日和 READY 日。
- READY 发布时同时覆盖冻结个人结算名单和结算过程中动态加入的锁定玩家。
- 玩家点击只结束黑屏等待；有出货、升级、职业或晕倒内容时，既有客户端结算序列继续播放。

## 离线农场追赶

- 玩家登录不再同步遍历整个农场，而是创建以农场 owner 为键的服务端任务。
- 任务按绝对日推进，每日依次处理作物、树苗和最终洒水器状态；每个 tick 同时受纳秒预算和条目上限控制。
- 每完成一个绝对日就更新 `lastOnlineDay`、对应季节并标记 SavedData dirty。崩溃或异常后最多重试当前未提交日，不会重放已提交日期。
- 同一共享农场只允许一个任务；成员登录只复用或扩展目标日。
- 追赶期间玩家不能在星露谷相关维度进行移动、传送、交互或 C2S 游戏操作；完成后解除追赶锁。
- 日结协调器活跃时暂停离线追赶，防止两个游标同时修改农场。

## 区块租约

- 条目开始前只租用该条目实际需要的区块。
- 条目关闭时立即尝试释放；成功释放的区块不保留到整个日结结束。
- 如果释放失败，业务游标仍视为成功，失败租约保留在根作用域中并由清理阶段重试，避免重复执行不可逆业务修改。
- 根作用域只保存释放失败的租约，不保存所有曾访问区块。

## 可观测性与测试

- 保留现有日结预算、overshoot、同步区块加载和子系统耗时统计。
- 离线追赶增加任务数、处理条目、单 tick 耗时、同步区块加载和失败计数。
- 单元测试覆盖：无农场在线玩家完整个人结算、晚登录空 READY、旧 pending 优先、真实晕倒只显示一次、逐日追赶游标、共享农场任务去重、条目级租约立即释放和失败后根清理重试。
- 性能基线文档改为中文；实服仍以 Spark 和 `/stardew perf status` 为最终证据。

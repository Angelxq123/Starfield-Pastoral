# 远古斑点：原作源码、素材与当前实现对照

2026-09-07。本轮完成地形传播/掉落修正，并研究远古斑点重制方向；尚未修改斑点生成、掉落或美术。以下原作结论来自项目本地 `源文件/` 的实际源码与解包素材，不以旧注释或网上概述代替代码。原始素材仅用于本地参考展示，没有加入生产贴图。

## 最重要的结构区别

原作把斑点放在 `GameLocation.objects`，底下地图地面独立存在。世界绘制使用透明的小型动态标记，不把整个地面换成“带虫子的黄土”。当前 `ArtifactSpotBlock` 替换脚下整块地面，只记录新泥土/旧黄土/砂地身份，没有保存原泥土 `variant`；模型仍指向旧黄土，未进入四季地形与连接包装器。

因此重制首先应分开 **地面、斑点类型、动画、生命周期、掉落**。美术上重画整块土无法修复这个结构问题。

### 可观察到的绘画方法

- 仅三条短笔触，中间较高、两边较低，疏密和高度不完全对称；中心之外保留大量透明留白。
- 根部暗、上部暖亮，靠少量明度变化形成嵌入地面的感觉。种子斑点使用绿尖、暗根，与普通斑点区分。
- 帧间改变局部倾斜和弯曲，根部保持稳定；有停顿，避免整张地图持续抖动。
- 当前泥土版把标记与土色揉在一起，轮廓与动作都弱；海滩模型直接继承沙漠斑点模型，两者共用沙地贴图。
- 后续原创 16x 贴图应保留这种轮廓、留白与节奏，用局部根影和尖部亮色提高辨识度；不能靠全地面加纹、加大虫体或增加碎几何提高所谓完成度。

## 生命周期与生成

主要入口：`StardewValley/GameLocation.cs:15132` 的 `spawnObjects()`；斑点分支从 15193 开始。

1. 普通斑点与种子斑点一起统计。每次执行这段生成逻辑时，各旧斑点有 15% 概率消失；姜岛北部 X<26 有保留例外。
2. 非冬季，农场已有至少 1 个、其他地图已有至少 2 个就停止新增。冬季现存超过 4 个才停止。这是**进入生成循环前的阈值**，不是循环中保证绝不超出的硬上限。
3. 尝试概率从 1 开始，每轮乘 0.75；冬季另外加 0.10。尝试会随机选地图坐标，很多坐标因放置条件不成立而失败。
4. 要求可放置、未占用、无遮挡前景、不在灌木后方，并且地面可挖；冬季额外允许地图上标为 Grass 的地面。森林特定区域被排除。
5. 成功放置时约 16.6% 选择种子斑点，其余选择普通斑点。该百分比不是每方块每天生成的概率。
6. `GameLocation.cs:5121` 的日期更新在每月第 7/14/21/28 天、月初及开局前几天存在额外 `spawnObjects()` 调用。因此不能把所有情况简化成“每天只执行一次 15% 消失”。
7. `GameLocation.cs:5210`：每月第 9 天，Backwoods `(18,18)` 会尝试放置种子斑点，并先清理该格耕地。
8. `StardewValley.Locations/Mountain.cs:270`：采石场补充生成有独立分支，其中种子斑点比例是 15%，不能一律套用 16.6%。
9. `Object.cs:3246`：寻宝图腾按半径 4、距离四舍五入等于 3 的环生成普通斑点，沿用地面与占用条件，并增加世界 `TreasureTotemsUsed` 计数。

## 挖掘与掉落

`Object.cs:1310`：锄头命中两种斑点后增加 `ArtifactSpotsDug`，尝试防御书；种子斑点走季节种子函数，普通斑点走地点掉落。之后调用 `makeHoeDirt(ignoreChecks:true)`、播放 `hoeHit`、获得 15 点采集经验并移除标记。此处是原作行为，**并不自动授权本项目所有草地变为可耕地**；重制需要保留用户已经确定的“自有草地不能耕”规则。

`GameLocation.cs:14263`：

- 使用日期、存档、坐标以及图腾累计次数构造随机源；不是直接消费全局随机流。
- 合并 `Data/Locations` 的 Default 与当前地点 `ArtifactSpots`，按 `Precedence` 排序。
- 每条规则依次判断 `Chance` 与 `Condition`，解析 `ItemId`/随机条目和数量；`ContinueOnDrop` 决定命中后是否继续。
- `ItemQueryResolver.cs:452` 的 `RANDOM_ARTIFACT_FOR_DIG_SPOT` 按物品数据迭代顺序读取 `ArtifactSpotChances`，返回首个命中的古物。**考古学家**附魔把此处概率乘 2，不是把所有产物数量乘 2。
- **慷慨**附魔仅对允许 `ApplyGenerousEnchantment` 的成功条目，以 50% 概率额外给同种物品并重新应用数量字段；不是完整重跑全部掉落表。
- 存在独立额外奖励：见过飞机后的神秘盒；`Utility.cs:6433` 的稀有物件检查（动物饼干、外观物品、技能书，带各自进度条件）；防御书在对象工具分支单独处理。
- `IslandLocation.cs:311` 在基础掉落前增加金色椰子、芋头块茎、古物宝箱分支。
- `DesertFestival.cs:338` 先掉 3–6 个彩蛋，然后继续基础斑点掉落，不是只给彩蛋并结束。

数据摘录包含 **22 个有斑点配置的地点组、90 条地点规则、33 个带地点概率的物品定义**；Default 有 11 条。它们是数据条目数量，不是互斥概率桶，不能简单相加得总概率。完整原始字段已保存在研究 JSON 中。

## 当前项目：已具备与明确差异

| 项目 | 已核对的当前实现 | 重制时要处理 |
| --- | --- | --- |
| 方块表示 | 3 个基底型斑点 ID；完整地面替换；只有新旧土/沙标志 | 标记与地面解耦，保留季节、变体、草缘连接 |
| 美术 | 静态整块黄土/沙地纹理，无 `.mcmeta` 动画 | 原创透明动态标记；先做普通、种子两类 |
| 种子斑点 | 原始 Objects 数据存在，但未找到运行时斑点注册和生成分支 | 补生成类型、种子选择、视觉区分 |
| 生成 | 已有农场、主图、海滩和沙漠生成；消失与冬季尝试衰减存在 | 当前按已加载区块、区块初次加载兜底、海滩/沙漠额外概率生成；并非原作逐地点机制 |
| 冬季草地 | `matchesSurface` 只接受土/沙 | 原作允许冬季 Grass；需结合本项目雪地和不可耕草规则制定挖后行为 |
| 原土恢复 | `TERRAIN_BACKED` 能恢复自有泥土，但固定为 variant=0 | 存在原变体丢失，独立标记可避免 |
| 地点掉落 | 运行时代码确实合并 Default；峡谷普通户外合为 OtherOutdoorsMixed，海滩/沙漠独立 | 类注释仍写“不执行 Default”，已过时；应以方法实现为准。是否恢复逐地点需要单独决定 |
| 附魔 | 锄头的慷慨分支完整重抽一次；古物随机函数没有考古学家倍率入参 | 与原作有明确差异，不能只复制 JSON 宣称对齐 |
| 防御书 | 已有统计与首次掉落递增概率 | 保留已有实现，随机源与调用归属需统一 |
| 沙漠节日 | 当前给彩蛋后直接 return | 原作之后继续基础掉落 |
| 随机源 | `rollDrops` 使用 `level.getRandom()` | 若对齐原作，需要稳定坐标/日期/世界种子，以及图腾计数 |
| 对外扩展 | `StardewArtifactSpotDrops`、世界掉落池和快照接口已经存在 | 保留扩展契约及现有 GameTests，避免重制删掉外部入口 |

当前源码入口：`block/nature/ArtifactSpotBlock.java`、`manager/ArtifactSpotSpawnService.java`、`manager/ArtifactDropService.java`、`item/tool/HoeItem.java`、`book/BookAcquisitionService.java`、`mastery/effect/TreasureTotemService.java`。

## 建议下一步

先做 **普通动态斑点 + 独立于地面的标记** 打样。可以用无碰撞原生方块表示地面上方的标记，让下方方块继续保有自己的 ID、variant、季节外观及连接；挖掘、消失只移除标记。素材保持原创 16x，先验证棕土、冰土、雪草与沙地上的可辨识性。

再加入种子斑点及生成规则，最后逐项调整掉落、附魔、图腾和地点配置。原作“冬季草上挖出耕地”与本项目“草地不可耕”、原作地点表与本项目混合户外表都是设计差异，不能未经讨论全部抹平。

# 草地顶面连接

当前层级为 **深色草 > 普通草 > 润湿耕地 > 干耕地 > 泥土**。耕地垄沟只在自身边缘收束，不向泥土绘制垄沟。连接仅改变邻接顶面的外观，不修改方块状态、存档、掉落或生长传播逻辑。

| 方块 | 受到的覆盖 |
| --- | --- |
| `dark_grass_block` | 无 |
| `grass_block` | 邻接深色草 |
| `dirt` | 邻接普通草、深色草；交叠像素由深色草优先 |

旧建筑泥土、草地、深色草地已删除注册，直接使用三个新 ID，不提供旧 ID 别名或存档迁移。原有特殊农耕黄土 `yellow_dirt` 与原版方块不参与。只检测相同 Y 高度的四个正邻居和四个斜邻居，不跨台阶。花和短草等无碰撞植物允许连接；积雪、流体、实体遮盖阻止连接。雪态草模型不参与。

## 实现

研究依据是 [Continuity 连接纹理规范](https://github.com/PepperCode1/Continuity/wiki/Continuity-Connected-Textures-Specification) 与 [OptiFine 官方 overlay 文档](https://github.com/sp614x/optifine/blob/master/OptiFineDoc/doc/ctm.properties)。借鉴其根据邻接关系选择透明覆盖纹理的思路，使用本项目 NeoForge 1.21.1 客户端模型接口实现；没有增加 Continuity 运行依赖，也不是一套通用 CTM 规则加载器。

`GrassTransitionModels` 在模型烘焙时仅包装普通草、泥土的非雪态方块模型，通过 `ModelData` 获取邻居。两类来源各自保存一个八邻接位掩码。边缘已覆盖的斜角无需重复绘制，因此每类来源对应 46 张非空覆盖图，加上空状态共 47 种。

`GrassConnectionMask.connections` 根据接收方层级过滤来源：泥土接收两类草，普通草只接收深色草，最高层级不接收覆盖。普通草覆盖面位于模型 Y=16.01，深色草面位于 Y=16.02，保证交汇处的深色像素位于普通草之上，不采用同深度相争的两个面。两个覆盖面都是原生 JSON 顶面，纹素密度为 1 像素/模型单位；没有改变主体立方体或碰撞盒。

固定色原始纹理及两套覆盖纹理位于 `assets/stardewcraft/textures/block/terrain`。普通草使用已认可的 v4 草顶和已认可侧面；深色草按同一像素稿重新配色，侧边仅调整草色，保留土和赭色根须。新泥土使用已认可的赭土稿，采掘掉落自身，禁止自然草传播覆盖，锄地转为自有耕地。项目的普通草、深色草及新泥土模型已指向这些纹理；旧建筑三类资源已移除。

覆盖图使用对应草顶的实际像素，四边有连续草皮与长短不同的叶尖，角落使用局部草簇。换用不同草顶的资源包时，应一并提供相应覆盖图；生成脚本可从仓库中的基础草顶重新生成。

## 独立地形方块

规范 ID 为 `stardewcraft:dirt`、`stardewcraft:grass_block`、`stardewcraft:dark_grass_block`，中文名为泥土、草地、深色草地。方块、物品、模型、掉落表、生态标签和客户端连接均使用新 ID。创造目录中的旧条目由新条目替换。草退化与羊吃草产生自有泥土；普通采掘直接掉落对应草地，无需精准采集。自有泥土禁止被草或菌丝自然覆盖。特殊农耕黄土不并入此地形家族。

`TerrainVariantWeights` 给出百分位分配。`TerrainVariants` 在服务端放置时抽取一次，固定复制的物品则先读取原生 `minecraft:block_state` 组件中的 `variant`。正常物品不写入该组件，因此一个物品堆里的每次放置独立抽取；普通中键取得普通物品，创造模式 Ctrl＋中键只复制具体 variant（含 0），连续放置固定外观。沿用原版 Ctrl-pick 的平台快捷键判断。雪态与连接方向均不写入物品，放置后仍由环境决定。固定复制的物品栏模型也匹配所选变体。

`VariedTerrainGrassBlock` 给普通草添加三种状态，`TerrainDirtBlock` 添加五种；普通草每种状态都有雪态模型。连接包装器原本就遍历所有状态，邻居判断使用方块身份，所有变体自动共享原体的规则和已有覆盖图，仍为深色草 > 草地 > 泥土。

仅玩家普通放置执行本次权重；现有地面、命令默认状态、生长/退化产生的默认状态不批量随机化。采掘掉落沿用原规则；固定外观通过 Ctrl-pick 获得。

## 游戏内季节切换（2026-09-07）

当前规则：春季（0）、夏季（1）、秋季（2）、冬季（3）分别使用独立绘制的对应季节材质。未同步时间或退出世界后回退春季。使用服务器同步的星露谷日历，适用于三个自有地形方块、自有耕地及其物品，不再限定旧染色器的峡谷维度。物理积雪仍依照原版 snowy 状态处理，不因日历到冬季自动给贴图泛白。

`TerrainSeasonTextures` 只负责材质集与模型路径选择，输入的 variant 始终保持原值。大土痕切夏季后仍是大土痕；草簇、动态小花、草丛、小土痕和碎石同理。没有添加 season 方块属性，没有写世界方块、重抽权重或修改 Ctrl-pick 组件；同一固定复制物品随日历更换配色，具体变体不变。

`GrassTransitionModels` 同时加载四季的 52 个地形/雪态模型、8 个干湿耕地模型和 368 个草边缘覆盖模型。区块重建时将本次材质集捕获到 `ModelData`，主体与覆盖边缘使用同一季节，保留原邻接层级。侧面、底面、粒子纹理同步选择。四类物品的运行时模型解析读取原 `minecraft:block_state` 中的 variant，选择同季同变体，支持物品栏、手持和掉落物；先前仅适用春季的静态物品 predicate 已由该解析器替代。

`StardewTimeHud.updateClientTime` 收到日历变化后调用客户端地形刷新（`levelRenderer.allChanged`），不需要玩家敲掉重放。一天内重复的时间同步不反复刷新。退出世界清理季节缓存，避免上一世界的夏季外观泄漏到尚未同步的新世界。资源重载会重新烘焙四季模型，材质选择继续读取当前同步状态。

旧渲染删除范围：移除 `StardewCraftClient` 对原版 `Blocks.GRASS_BLOCK` 的季节色覆盖，使其恢复原版生物群系颜色；移除旧 `YELLOW_DIRT` 与 `ARTIFACT_SPOT_DIRT` 的冬季染白注册及专用函数/常量。树叶、蕨类、独立高矮草与牧草的旧季节颜色不在本次删除范围。

夏季 PNG 和模型现位于生产资源的 `block/terrain/summer` 路径，脱离研究目录也能构建。春季绘画、变体状态定义、复制逻辑与概率均未修改。制作目录中的“未接入”说明保留为历史阶段记录。

## 四季耕地与地图资源接入（2026-09-07）

`stardewcraft:farmland` 是原生 `FarmBlock` 的子类，顶面与碰撞箱现均采用原版 15/16 高度（后续用户调整，取代最初完整方块高度的要求）。保留原生 `moisture=0..7`，0 使用干材质，1..7 使用湿材质。春、夏、秋分别使用认可的土质垄沟，冬季采用冰质垄沟：干态覆霜，湿态为较深、通透的蓝冰。日期切换仅选择材质，不更改湿度、地形 variant、作物或固定复制物品的组件。

仅自有泥土的五个变体可以锄成自有耕地；自有普通草、深色草均不能锄。原版泥土的锄地行为与旧黄土、原版耕地继续保留，以支持已有农场。项目现有浇水壶、洒水器、肥料、作物和过夜湿度系统使用原生耕地接口；新耕地接入相同流程。峡谷维度仍沿用项目既有每日浇水规则，维度外沿用原版临水湿润和退化。新耕地退化、采掘及杂物覆盖恢复自有泥土；旧耕地的原有恢复规则不变。古物斑点记录新旧泥土身份，挖掘后恢复对应地面。

### 连接

普通草与深色草的连接继续覆盖泥土和干湿耕地。润湿耕地向干耕地渐变；遇到泥土时，在耕地内部的 1–4px 边带收束垄沟。同一个角落先计算湿度混合，再收束为泥土，最后叠加对应季节草缘。相邻耕地不额外绘制边框，保留认可稿沿垄沟方向的连续纹理。

`TerrainFarmlandEdges` 计算 16×16 网格的四档混合权重。`generate_farmland_blends.py` 从生产贴图生成每季 20 张混合纹理及原生顶面模型；`TerrainFarmlandQuads` 将同档连续像素合并为矩形，裁切烘焙后的原生顶面，精确保持 UV 与 16x 像素网格。它替换自身顶面，不叠放同高度表面，也不改变碰撞箱。

### 地图升级

`replace_pregen_terrain.py` 只修改打包资源中的 MCA 和 schem，不访问玩家存档。映射为原版草方块 → `stardewcraft:grass_block`，原版泥土与旧黄土 → `stardewcraft:dirt`。区块保留原有方块索引、坐标、实体及其他 NBT；schem 合并重复目标状态时同步映射索引，并保留旧文件已有的缺失调色板引用。完整记录见 `terrain-map-replacement.json`。

地图版本从 13 升至 14，更新公共预生成地区及新建农场模板。已有农场的初始化标记、注册和实例区域不重置；安装器继续排除玩家农场与动态室内区域。旧农场保留旧地面，新农场使用更新后的模板。

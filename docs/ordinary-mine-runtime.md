# 普通矿井运行时（0–120 层）

普通矿井与骷髅矿井均使用已审批的 `mine_layouts` 建筑资源；旧随机洞室生成器和旧石材已完全删除。不会修改制作工坊存档，也不改变已批准的石头模型、AABB、采掘时间与能量标准。

## 入口和地图

- `OrdinaryMineRuntime` 安放大厅及 1–120 层。建筑 NBT 与对应 JSON 的尺寸先校验，再写世界；资源缺失会报错，不退回旧随机洞室。
- `OrdinaryMineLayout` 用 `tile_origin` 将原版 X/Y 地块映射成 MC X/Z。出生点由 `spawn_relative` 决定，楼层间距仍为 200。
- 实际第 30、50、90 层分别复用 10、40、80 的建筑稿；第 30 层同时将地面、岩壁及带 `theme` 状态的构件切成幽暗大地。
- 矿洞入口、楼层传送和矿车到站先同步目标层数。矿车站及铁轨采用大厅模板中的版本，地表站点初始化不再生成矿井大厅或另放矿车。
- 到底后的普通额外布局按 `MineShaft.loadLevel` 的 6% 分支及重掷规则选择。仅使用已打包的对应主题模板；抽到无现有模板的布局时仍使用本层基础布局。危险、感染、史前、采石场矿洞等特殊区域不启用。
- 模板里的岩壁、地板和装饰保留建筑身份，生存破坏及炸弹不能拆掉它们。刷新时会清除前一布局超出新布局边界的部分及旧实体。

## 填充与采掘

`OrdinaryMinePopulation` 对照 `MineShaft.populateLevel / createLitterObject / getMonsterForThisLevel / tryToAddOreClumps`，按原版 X 外层、Y 内层次序执行：

1. 石头密度在 10–29% 中取值；怪物密度在 0.2–2.19% 中取值；拾取物基础概率 0.25%。第 1 层无初始怪物，第 1 层及五的倍数层无普通拾取物；十的倍数奖励室不填充普通资源。
2. 保留边缘桶箱、平台地块 257 的桶箱分支、石头优先的互斥判定、幼虫/灰尘精灵邻接群组、大石块占地、清空石群、开场梯子单次尝试及递归矿簇。
3. 普通/宝石/金属节点使用 `mine_node_sources/ordinary_stones.json` 的原版 ID 映射与实际节点方块。水晶、蘑菇沿用现有地面模型。冰层 319–321 作为不计数的易碎冰体，复用已批准的覆壁冰体资源旋转落地，不再冒充冰泪奖励。
4. 怪物类型、生成分支及特殊物品池来自原版；战斗实体、AI、属性适配继续使用项目既有 `MineMonsterSpawnHandler` / combat profiles。本轮没有重做怪物模型和战斗系统。
5. 每十个游戏分钟执行飞行怪物判定；保留蒜油、30–40 秒雾袭、每四秒一波与最后五秒停止增援。原版屏幕外生成点在 MC 中投射到对应边缘最近的可达空格，避免生成在岩壁内部。雾使用 MC 雾色/雾距接口，不承诺各光影包呈现完全相同。

初始石头计数与实际可破坏节点集合分开：原版递归矿簇不增加 `stonesLeft`，但每个节点只能结算一次。怪物 UUID 同样只注销一次，包括环境伤害导致的死亡。

采掘时间和能量没有重新调速，沿用 `MineStoneMining.requiredSwings / breakTicks / energyCost` 中已审批的整次挥镐次数、MC 镐等级速度优势和逐次能量公式。普通矿井节点的梯子判定与节点掉落共享原版日期/坐标随机流：先跳过一次随机数，再扣石头、判梯子、结算掉落。地图填充使用 MC 的存档随机源；相同数字种子不等于两款游戏产生逐格相同的随机结果。

## 梯子、刷新和宝箱

- 下行梯子替换站立格下方的对应主题矿井土；岩壁、已有障碍和 120 层不能生成下行梯子。建筑中原有的固定下行梯子继续保留。
- 石头梯子使用原版剩余石头、幸运、清怪与矮人祝福公式。怪物死亡独立执行 15%（祝福额外 7%）判定；已有一个梯子不禁止后续击杀梯子，击杀梯子也不耗掉原版石头梯子标志。
- 以绝对天数判断隔日刷新。没有玩家或当天断线玩家占用的更深楼层会失效；较浅楼层保留到相应刷新时机。重新进入有效楼层不重新安放建筑、资源或奖励箱。
- 平台桶箱剩余数量、已取空的矿车/背包独立保存；楼层重建不会自动补回。年度清理沿用原版平台/煤炭缓存规则。
- 奖励箱坐标为原版 `(9,9)`，20/60/100 层为 `(9,13)`，第 30 层没有奖励箱。开启与领取分开按玩家 UUID 保存；玩家 A 开过后，A 的箱盖永久保持打开，B 的箱盖和奖励不受影响。重进区块、重新生成楼层及重载记录不会恢复已领取奖励。
- 奖励容器不能存入玩家物品或整理/改色。广播的方块实体更新不包含任何玩家库存；开启状态只发给对应玩家。
- 第 20 层修正为钢制轻剑，第 90 层修正为黑曜石之刃。按用户本轮要求，**弹弓暂不制作**：第 40 层暂用 `cutlass`，第 70 层暂用 `tempered_broadsword`。以后仅需在 `mine_chest/rewards.json` 换回已完成的弹弓物品。
- 20/60/100 层矿湖使用对应 `mines_20/60/100` 群系。光照按实际模板范围排队，并等待传播完成后向已追踪区块的玩家重发光照及群系数据。

## 矿井桶箱交互与掉落（2026-09-09）

按本轮决定保留一击打碎，不移植原版三点容器生命值。桶与板条箱共享内容规则；武器、镐、斧、锄可命中，普通空挥读取服务端挥手状态，并遵守攻击间隔和技能普攻锁定。近战范围沿用剑、匕首、棍棒各自的范围；直接点到桶箱也不能绕过遮挡。

- 主格与上半格统一回溯到主格，武器、正常方块破坏及模组炸弹传递实际破坏者。上半格被炸也只移除一只容器、结算一次；创造破坏不发奖。没有破坏者时不借用附近玩家的通底、解锁或精通资格。
- 内容随机流按原版 `CreateRandom(tileX, tileY * 10000, DaysPlayed, mineLevel)` 建立，普通矿井使用布局 `tile_origin` 还原原版地块坐标，不混入 MC 世界随机数。主题表使用双精度概率判断并保留空项及必要的随机抽取次数。
- 20% 提前返回分支中，再有 10% 概率掉季节种子；种子数量、幸运额外数量、春季 23 日之后／其他季节 20 日之后转入下季均复用已有原版规则。
- 神秘盒需要既有 `sawQiPlane` 解锁标记；基础率为 `0.0081 + 团队平均每日幸运 / 15`，再应用谜之书的 `0.66 / 0.88` 系数。采集精通者改掉金色神秘盒。战斗精通饰品仍使用独立随机源及对应层数、幸运公式，资格改为实际破坏者。
- 稀有奖励使用 `Utility.trySpawnRareObject` 的 `1.5` 倍参数：耕种精通金色动物饼干、第三日起的已注册服饰与技能书。齐豆任务视为未开启；无映射家具等缺失奖励直接跳过，不用其他物品顶替。
- 范围技能通过 `MineBarrelBreakHandler.breakInVolume` 在实际伤害帧接入。目前接入弯刀月牙斩、龙息审判、铅棒／短棍技能、银河锤／无限锤的扫击、震荡和捶击；此接口没有把所有自定义技能动画一律当作范围伤害，其他自定义技能仍需按各自命中形状接入。

现有普通矿井桶箱实例直接使用以上代码，不需要为了更换掉落规则重建地图。

本次验证：`./gradlew classes runGameTestServer -PgameTestNamespaces=stardewcraft_mine_assets` 通过，13 项测试全部通过（既有 5 项构件测试与新增 8 项桶箱测试）。覆盖季节及季末种子、神秘盒解锁／幸运／精通、稀有奖励与缺失家具跳过、随机流隔离、实际玩家归属、上半格爆炸、防重复掉落、创造破坏、空挥／间隔／遮挡／技能锁、范围攻击无怪物时的命中，以及附近战斗精通玩家不能替破坏者取得饰品资格。没有启动游戏客户端。

## 范围与验证

本轮完成上述普通矿井核心循环。原版随机地面杂草、随机旧矿工小径及二维环境光随机化尚未迁移；墙饰、植物点缀、路径与灯具仍保留审批过的建筑稿。原版武器随机固有词条也没有在本轮扩展。这里不能据此宣称整个 `MineShaft` 已逐分支完全复刻。

验证不读取本地 `源文件/`、`tmp/` 或制作工坊。原版源码只用于开发对照。

- `./gradlew classes checkTranslations` 通过。
- `stardewcraft_ground_stone` 33 项定向采掘测试通过。
- `stardewcraft_ordinary_mine` 10 项定向测试通过：每次实际重建大厅及 1–120 层、原版节点映射、奖励坐标与矿湖群系、重复进入保留、土层梯子、开启/领取记录隔离、真实宝箱库存与重建后的领奖防重、桶箱/煤炭/断线记录持久化、所有已打包普通额外布局尺寸、光照传播和旧布局边界清理。
- 这些是无窗口服务端测试。GameTestServer 不加载自定义矿井维度，因此完整建筑测试在测试世界中安放真实资源；跨维度传送和实际双客户端箱盖观感尚未进行游戏内人工验收。
- 没有启动额外游戏客户端、打包 JAR、提交或推送。
